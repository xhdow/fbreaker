
# 项目概述
fbreaker 是一个批量加密视频文件头部的小工具。

**速度极快**：实测在 SSD 上，加/解密 1100 个视频文件不到 1 秒完成。

**为什么快**：
- 只加密文件头部的关键字节，且原地覆写，不复制、不重写整个文件，I/O 量极小。
- 利用 Go 的轻量并发，在 SSD 的高 IOPS 下能有效重叠每次文件操作的延迟。

# 用法

```
fbreaker [-c N] <encode|decode|info|clearmeta> <password> [dir_or_file]
```

## 选项
- `-c N`：并发数，默认 4，最小 1

## 命令

| 命令 | 说明 |
|------|------|
| `encode` | 加密目录/文件（原地修改文件头，尾部追加密文元数据） |
| `decode` | 解密目录/文件（按尾部元数据还原文件头并恢复原文件名） |
| `info` | 查看指定文件是否加密及元数据信息 |
| `clearmeta` | 仅移除尾部元数据（保留已加密的文件头，不做解密） |

## 示例

```bash
# 加密目录（8 并发）
fbreaker -c 8 encode 123456 ./data

# 解密目录
fbreaker -c 8 decode 123456 ./data

# 查看文件加密信息
fbreaker info 123456 ./data/somefile

# 仅清除元数据（不解密文件头）
fbreaker -c 8 clearmeta 123456 ./data
```

# V2 算法

## 加密算法

对文件头指定字节长度的数据加密后写回。具体加密算法为：对密码进行 MD5 运算得到密钥，再用密钥使用 AES-GCM 进行加密。

- 默认加密文件头 512 字节（若文件实际大小小于此值，则加密其全部内容）
- 密钥 = MD5(password)
- 使用随机 12 字节 nonce
- 加密后的纯密文写回文件头（长度不变，原地修改，不复制整文件）
- nonce 和 GCM 认证标签存储在文件尾部元数据中

## 文件末尾元信息

文件末尾元信息只在加密后的文件中存在，未加密文件不应该存在。

文件布局：

```
[已加密的文件头 ndata 字节][文件其余内容...][cryptinfo][ncryptinfo]
```

cryptinfo 结构（按写入顺序）：

| 字段 | 长度 | 说明 |
|------|------|------|
| ndata | 4 字节 | 被加密的文件头字节数（含 nonce） |
| nonce | 12 字节 | AES-GCM 随机数 |
| tag | 16 字节 | AES-GCM 认证标签 |
| md5 | 16 字节 | 密码的 MD5（用于快速校验密码是否匹配） |
| fname | nfname 字节 | 原文件名 UTF-8 编码后按位取反 |
| nfname | 4 字节 | 原文件名长度 |
| magic | 4 字节 | "XYXY" 代表 V2 版本 |
| padding | 0~255 字节 | 随机填充（用于伪装尾部长度） |
| npadding | 4 字节 | 填充字节数 |

文件最末 4 字节固定为 ncryptinfo（即 cryptinfo 的总长度），这样无需扫描即可定位元数据。

## 加密后的文件名

加密后的文件名随机化伪装为 16 位 hex 字符串，无扩展名。例如：`3a7f9c2e1b8d4f60`

# 安全特性

- **防重复加密**：encode 命令会检测文件是否已加密，已加密文件自动跳过
- **防误解密**：decode 命令会检测文件是否已加密，未加密文件自动跳过
- **密码校验**：解密前先校验密码 MD5，密码错误立即返回
- **并发安全**：使用原子操作统计，goroutine 并发处理文件
